toyengine

A modern C++20 / Vulkan 3D game engine with a Blender-style editor.

C++20VulkanMoltenVKLinuxmacOSYAML sceneseditor + hub

toyengine pairs a full-resolution deferred PBR renderer with volumetric fog and light, particles, rigid-body and cloth physics, dynamic water, streamed procedural terrain, animation, 3D audio, an interactive UI toolkit and a native editor that writes exactly the files the game loads. It is adaptable by design: scenes, objects, materials and render settings are plain YAML, every rendering feature has quality tiers and a master switch, and each subsystem is its own library that can be lifted out and used elsewhere.

What's inside

Rendering, simulation, worlds and sound

Rendering

  • Deferred PBR: Cook-Torrance with directional, point and spot lights, sky and environment
  • Cascaded sun shadows with cascade blending; many shadowed local lights in one atlas, with static casters cached
  • Soft PCF, optional PCSS and single-ray contact shadows
  • Hi-Z SSR, traced SSGI and GTAO-style SSAO, with per-object motion vectors feeding the temporal filters and TAA
  • Bloom, auto exposure, LUTs, physical DoF, tilt-shift, TAA / SMAA / FXAA

Volumetrics and fog

  • Global analytic height fog
  • Local fog volumes, box or sphere: pockets, drifting haze, wind ribbons
  • Sun shafts that respect shadows, plus visible spotlight cones and lantern halos

Water

  • Lakes and oceans with Gerstner waves
  • The same wave math runs in the shader and in a CPU query, so gameplay matches visuals
  • Rivers whose current follows the mesh slope and bends around obstacles
  • Shoreline foam and ripple rings; Buoyancy floats any rigid body
  • Underwater fog, absorption, caustics, Snell's window

Particles

  • Unity-style modules: bursts, shapes, forces, curl-noise turbulence, colour and size over life, collision, sub-emitters
  • Blender-style emission from mesh faces, vertices or edges, and a hair-like scatter mode for instanced meshes
  • Simulated on the job system; sorted, instanced and soft-faded in the transparent pass with HDR glow
  • LightFlicker for firelight

Physics and cloth

  • Box, sphere, capsule and triangle-mesh colliders
  • Physics materials, hinge joints, triggers, collision layers
  • Kinematic movers and character controllers
  • XPBD cloth that collides with the world and renders as a shaded, shadow-casting mesh

Procedural terrain

  • A seeded mapcoopa world with elevation, biomes and rivers
  • Meshed in chunks on the job system, streamed around the camera
  • Tile shapes are mesh assets, so one line of YAML changes the look

Animation

  • Keyframed clips on object-hierarchy rigs, driven by an Animator with states
  • Skinned meshes that bend with vertex-group weights
  • Keyed in the editor's timeline and dope sheet with record mode and auto-keying

UI toolkit

  • Panels, text, buttons, sliders, progress bars, layouts, masks
  • Themed composites: windows, menus, stat bars, hotbars, setting rows
  • Crisp screen-space HUDs, or world-space canvases that stay clickable in 3D

Audio

  • WAV and MP3 clips through a bus mixer (Master, Music, SFX, UI)
  • Binaural 3D panning, distance falloff and doppler
  • AudioSource and AudioListener components; settings sliders bind straight to buses

toyengine_editor

An editor that feels like Blender

The editor embeds the real engine, so its Full Render viewport is the game's renderer. Blender's keymaps, gizmos, modes and outliner, with Unity's component model.

  • Scenes and object assets. Hierarchy, inspector, gizmos, and play / pause / step in place. Prefab-style assets are instanced with prefab:.
  • Mesh modelling. Extrude, inset, bevel, loop cut and slide, bridge, Catmull-Clark subdivide, mirror and UVs. Sculpt, vertex paint and weight paint modes.
  • Animation. A timeline and dope sheet with record mode: move a rig and the changed channels are keyed.
  • Material lookdev and UI design. A shader ball with studio lighting, and a UI designer drawn by the game's own UI pass.
  • Render and project settings, applied live.
  • Plain files. Everything saves as YAML in assets/, ready to hand-edit, diff and merge.

Data-driven

A scene is a file you can read

Scenes are trees of objects with components, written in YAML. The demo scenes are heavily commented and double as the reference for every component, and config.yaml has a comment on every key. Packaged builds use binary .caml (Zstandard + AES-256-GCM), and every loader reads both, so nothing needs path rewriting.

$git clone --recurse-submodules git@github.com:cooparobla/toyengine.git
$cmake -B build && cmake --build build -j
$./build/toyengine particles_test
$./build/toyengine_hub

On macOS, run tools/setup_macos.sh once first to install MoltenVK, the Vulkan loader, glslc and GLFW.

Projects and shipping

From a new project to a signed build

A game lives in its own project folder with its assets and C++ components. The project builds the engine alongside its own code, either pinned to a pushed commit for reproducible builds or linked to a local checkout for working on both at once.

  • toyengine Hub. Creates, adds, opens and re-pins projects, and streams the first build into its log.
  • Your code in the editor. Components in src/ compile into both the game and the editor, so Play runs them. Build › Refresh rebuilds both.
  • Build. A standalone game that runs without the engine repo or the Vulkan SDK: a .app on macOS with MoltenVK bundled, a folder on Linux.
  • Development or Shipping. Shipping is a Release build with encoded .caml assets, debug hooks off, and Developer ID signing with notarization on macOS.

The coopa stack

Seven libraries, stacked like bricks

toyengine sits on pinned submodules. Each is C++20, mostly header-only, builds standalone, and is useful without the engine.

toyengine

The engine and editor: render pipeline, water, streamed world, gameplay components.

gfxcoopa

Vulkan, from RAII device objects up to a deferred PBR renderer.

physxcoopa

Real-time rigid-body and cloth physics.

uicoopa

Anchored retained widgets, a fluent builder and an immediate-mode layer for tools.

sfxcoopa

Game audio with a bus mixer and binaural 3D sound.

mapcoopa

Seeded fantasy worlds: 33 biomes, rivers, roads, nations, towns and caves.

libcoopa

The shared runtime: work-stealing jobs, scene graph, async assets with hot reload, coroutines.

caml

YAML stored as compressed, encrypted .caml files. Library and CLI.
